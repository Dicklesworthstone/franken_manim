# Python runtime-payload provenance

Reproducible portal sessions now bind content hashes of the installed runtime,
not just `CPython 3.13`, a portal version, and a NumPy version. The same guarded
`RenderSession` is used by the console, free rendering functions, and both
`Scene` methods. Standalone `fmn` remains CPython-free.

```python
from pathlib import Path
from manimlib import Scene, Dot, RIGHT

sources = {"scene.py": Path(__file__).read_bytes()}
scene = Scene()
with scene.render_session(
    "output.png", format="png", resolution=(640, 360),
    reproducible=True, sources=sources,
) as session:
    scene.add(Dot().shift(RIGHT))

print(session.result.manifest)
print(session.result.closure_digest)
```

`Scene.render(...)` accepts the same `reproducible`, `sources`, and
`runtime_identities` keywords. A source provider is evaluated after scene
execution; use `lambda: loaded.sources` with the existing `SceneSource` loader
when local imports can occur during construction or teardown. An explicit source
mapping remains the caller's declaration, not automatic discovery of all effects.

## What is bound

The runtime snapshot hashes the selected CPython executable and configured
shared runtime library (when applicable), the portal's installed package
payload, and NumPy's installed payload including bundled libraries and data.
The ABI identity binds the interpreter version, cache tag, SOABI, ABI flags,
byte order, pointer width and the portal's declared ABI policy.

Package inventories come from installed wheel `RECORD` data, but its claimed
checksums are not trusted: actual files are read and hashed. The reader parses
`RECORD` directly because `importlib.metadata.Distribution.files` may filter out
missing files. Missing payloads, traversal, duplicate names, foreign loaded
modules, unknown runtime identities, and unverifiable installations are explicit
refusals. Standard rendering has neither this installation requirement nor the
hashing cost.

Identity strings use `installed-payload-sha256=...`. They are **not the original
wheel ZIP hash**, which cannot be recovered from an installation. Source files,
native libraries, package data, METADATA and WHEEL participate; generated bytecode
caches, installer bookkeeping and known generated console launchers do not.
Logical paths and sorted content records avoid incidental installation-prefix
and timestamp dependence. Sourceless loaded bytecode is refused.

Limits are 32,768 total payload files, 512 MiB per file, 2 GiB total payload,
and 8 MiB of RECORD text per distribution. Reads use bounded chunks and reject
nonregular files, growth, replacement and detectable changes during hashing.
No timestamp-only digest cache can hide a same-size/same-mtime edit.

## Publication and failure behavior

Runtime identities are acquired before native output acquisition. Legacy console
version labels remain accepted as an input spelling but are replaced by measured
identities; arbitrary caller-supplied labels cannot certify a different build.
The wheel's own build identity (C2) follows ADR-0025. A wheel built from edited
sources records `git:<commit>+dirty:<sha256>`. A wheel whose sources cannot be
named (`unidentified:`, `+unverified`) is refused when a render begins with
`reproducible=True`, before any output is acquired.

The source provider and its mapping are frozen before the first verification.
An intervening runtime change cancels the active native generation before
`_finish_render` publishes an artifact. Original callback failures, thread
confinement, no-clobber ownership and idempotent completion remain unchanged.

Native finalization can itself invoke final-frame camera hooks. A second runtime
verification runs before provenance publication. When a change occurs that late,
**the artifact may already exist**: the existing session reports
`artifact_published=True`, no successful `RenderResult`, and the incomplete
provenance note. It does not falsely claim rollback or publish a success sidecar.
There is no per-frame hashing.

## Evidence and limits

`test_runtime_identity.py` exercises real file and installation-metadata inputs.
`test_runtime_provenance_protocol.py` executes the existing `RenderSession` and
source-freezer code with an explicit native sink double. Neither suite proves
rendered output. `runtime_provenance.py`, registered in the installed-wheel gate,
requires the actual extension and tests both Scene front doors, native PNG/
manifest publication and rejection without output.

This strengthens the runtime component of the closure; it does not complete G4b.
It does not inventory arbitrary third-party imports, the entire standard library,
unbundled system libraries, GPU state or uncontrolled host effects. File snapshots
are not an attestation of already-loaded machine code or protection against an
adversarial host process rewriting both code and guards. Original wheel archive
identity, complete C1-C10 input closure and cross-platform certification remain
separate obligations. No subprocess or dependency is added.

Portal manifests record C3 the way native `fmn` does: the toolchain and the
Python runtime versions as the platform-neutral C3 item, and the target triple
and feature set as the `platform/target` item that the semantic digest leaves
out (docs/INPUT_CLOSURE.md §4). Each output is named by its file name in the
output directory, never a host path, so two platforms' manifests can be
compared with `fmn-manifest-compare`.
